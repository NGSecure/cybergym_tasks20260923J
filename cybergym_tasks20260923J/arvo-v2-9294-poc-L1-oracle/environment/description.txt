Rendering an OpenFlow packet-in message that embeds a crafted raw IPv6/UDP packet causes Open vSwitch's packet-printing code to read 2 bytes past the end of the embedded packet's buffer while fetching a transport-layer checksum field.

Root cause: before printing, the embedded packet is run through the same flow-key extraction logic used elsewhere in the packet-parsing library. Its IPv6 header validation checks the header's declared payload-length field against the total bytes remaining in the buffer rather than the bytes remaining after the fixed-size IPv6 header has been consumed, so a payload length that overstates the true remaining payload by up to one header's worth of bytes is accepted as valid. The printer then trusts this overstated remaining-length figure when deciding that a UDP header is fully present in the buffer and dereferences its checksum field, running off the end of the actual packet data.
