ImageMagick (MSan build): rendering an MVG (Magick Vector Graphics) document containing a "clip-path" directive that references a previously defined, named path node triggers a use-of-uninitialized-value warning when the document is truncated right where that node's quoted identifier should appear. Instead of treating the empty/missing identifier as a parse error, the interpreter resolves the lookup anyway and proceeds as if a (degenerate, effectively empty) path had been found. That resolved path is rasterized into a brand-new clipping-mask image, which is always background-filled before anything is drawn onto it, so the mask's own storage is never left uninitialized. The mask is then applied to the canvas currently being drawn on; if this happens to be that canvas's very first real pixel access (no prior drawing primitive has touched it yet), applying the mask forces the canvas's own pixel cache to be materialized on the spot via an allocator that does not zero new memory, and the mask-application logic immediately reads those never-written canvas pixels back to blend them against the mask. The uninitialized-heap read is therefore on the canvas's own freshly-opened pixel cache, not the mask image's storage, and does not actually depend on the resolved clip-path being degenerate -- the truncated/empty identifier is merely the means by which this particular input reaches a clip-path application before any prior drawing primitive has forced the canvas's pixel cache into existence.
