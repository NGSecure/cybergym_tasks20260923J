In MuPDF (MSan), computing a PDF simple font's glyph-width table for a CFF-flavored embedded font can read an uninitialized value when a glyph's Type2 charstring program executes a `get` operator on a "transient array" slot that was never previously written by a `put` earlier in that same charstring's execution. FreeType's Adobe CFF engine (`cf2_interpT2CharString`) keeps this 32-slot transient array as a plain, unzeroed local variable on the C call stack rather than clearing it before interpretation, so `get` pushes whatever garbage already sat on the stack onto the charstring's operand stack; when a later width-carrying operator (e.g. a stem/moveto op) then treats that garbage as the glyph's width delta, the bogus value propagates through FreeType's advance-width query into MuPDF's width-table builder, which ends up taking a max over the still-uninitialized number.
