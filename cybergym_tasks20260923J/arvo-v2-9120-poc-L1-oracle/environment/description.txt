Drawing an F32-format bitmap that was cleared via SkPixmap's SkColor4f erase() triggers a use-of-uninitialized-value warning during pixel compositing. Root cause: the per-row store loop that fills the F32 pixmap recomputes its destination pointer through a call to SkPixmap::writable_addr() with no row coordinate, which always resolves to the start of the buffer, so every loop pass overwrites the same first row instead of the one being processed and every other row is left holding whatever raw bytes the backing allocation happened to contain; when that bitmap is later used as a blit source, the pixel-store path that composites it onto the destination reads one of those never-written rows.
