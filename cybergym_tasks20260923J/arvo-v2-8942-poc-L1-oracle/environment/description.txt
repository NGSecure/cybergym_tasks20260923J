Disassembling certain x86 instruction bytes with capstone's cs_disasm() triggers an MSan use-of-uninitialized-value warning in the x86 decoder's opcode-ID resolution path. Root cause: the per-call instruction decode state keeps a field that records where a mandatory legacy prefix (0x66/0x67/0xf2/0xf3) was seen, but that field is only assigned along a subset of opcode-table dispatch branches inside the prefix-parsing routine; for input byte sequences whose dispatch never hits one of those branches, the field keeps whatever garbage was on the stack for that call, and a later mandatory-prefix disambiguation check (used to pick between SSE-prefixed and legacy encodings while resolving the instruction ID) reads and compares that still-uninitialized value.
