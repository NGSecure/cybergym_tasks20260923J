ImageMagick's Magick++ encoder fuzz target (MSan build), read-then-write round trip through the PSD coder: a use-of-uninitialized-value read fires while the decoded image is being re-serialized back out as a PSD file. Root cause: while parsing the input, the PSD reader enables an alpha channel on the in-memory image by calling the generic alpha-channel-enable helper, which forces the image's pixel cache to be (re)opened through a fresh heap allocation (posix_memalign) — memory that is not zero-filled. For the layer/channel combination in this particular input, only part of that freshly allocated pixel cache actually gets its alpha samples written by the PSD-specific channel-decoding code before the enable call returns; the image is left flagged as "has an alpha channel" even though not every pixel's alpha slot was populated. When the same image is subsequently written back out as PSD, the channel-export path that produces each output channel's byte stream pulls the alpha sample straight out of the pixel cache for every pixel and rescales it to the output sample depth without ever checking whether that particular slot was initialized, so pixels whose alpha value was never written by the reader are read and rescaled anyway — triggering the MSan use-of-uninitialized-value report during that per-pixel alpha rescale step, invoked from the PSD channel-writing routine.
