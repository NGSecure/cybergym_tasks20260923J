A crafted vector-graphics ("MVG"-style) drawing command containing an elliptical-arc path segment causes a heap-use-after-free WRITE while the image library converts that path into a concrete sequence of drawable points. Root cause: when the arc segment's two orientation flags (which arc to take / which sweep direction) are read from the input text, they are converted straight to booleans without checking whether the token actually contained a valid number the way the arc's coordinate and angle fields immediately around them do; a malformed or truncated flag token is therefore accepted silently instead of aborting parsing. Processing then continues into the routine that expands the arc into a run of curve segments and appends their points to a dynamically growable buffer; that buffer is grown on demand by freeing the old block and allocating a new, differently-addressed one whenever more segments need more room than is currently reserved. A pointer into this buffer that was computed earlier in the arc-expansion call chain is used again afterward to record bookkeeping for the segment (its point count and subpath state) without first being recomputed against the buffer's current, post-growth address, so that write executes against the block that the just-performed reallocation already freed.
