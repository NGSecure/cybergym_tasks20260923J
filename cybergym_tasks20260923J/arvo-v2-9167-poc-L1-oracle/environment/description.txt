Disassembling certain crafted x86 byte sequences with capstone's X86 decoder triggers a use-of-uninitialized-value report from the code path that copies the decoded per-instruction state into the public disassembly result, specifically when it reads the byte offset of the instruction's immediate operand.

Root cause: the offset fields for an instruction's immediate/displacement operands live in the on-stack, per-call internal decode-state struct, which is zero-initialized only up through a boundary marker partway through its field list; those offset fields were declared after that boundary, so on any decode where the immediate-reading step is never taken, the field is left holding whatever stack garbage was present from a prior call, and that garbage is later read (and branched on) when building the public result.
