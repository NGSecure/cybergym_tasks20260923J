A crafted BigTIFF file with a ZIP/Deflate-compressed strip triggers a use-of-uninitialized-value read inside zlib's internal Adler-32 checksum routine during TIFF strip decoding.

Root cause: when GraphicsMagick's TIFF reader decodes a ZIP-compressed strip (libtiff's tif_zip.c), a malformed/corrupted compressed stream makes the underlying zlib inflate() call report a decode error mid-strip; instead of aborting the strip on that error, the decoder called inflateSync() to resynchronize to the next flush point and then kept feeding more input into the same zlib stream. Because the stream's internal state was never cleanly completed by valid decompressed data before decoding resumed, a subsequent inflate() call ends up running the checksum update over stream/window bytes that were heap-allocated during stream setup but never actually written by real decompression output, so the checksum pass reads uninitialized heap memory.
