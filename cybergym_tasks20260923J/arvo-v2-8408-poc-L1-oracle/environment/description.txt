ImageMagick's MVG (Magick Vector Graphics) renderer draws an ellipse primitive by first estimating, from the primitive's declared radius, how many trace points it will need, and uses that estimate both to reject absurdly oversized primitives up front and to pre-size a shared point buffer before handing off to the routine that actually walks the arc and emits points. Root cause: for an ellipse with an extreme radius, that upfront size estimate lets the oversized-primitive guard pass even though the true radius is enormous, so rendering proceeds with a buffer only sized for a modest ellipse. The arc-walking step then independently recomputes the real point count on its own, radius-dependent step size; when it asks to grow the shared buffer to match, the requested growth is so large the allocation itself legitimately fails. Because the caller does not distinguish "no growth was needed" from "growth was attempted and failed," it treats both the same way and keeps depositing successive arc points through the pointer to the buffer that the failed growth attempt had already released out from under it, producing a heap-use-after-free write.
