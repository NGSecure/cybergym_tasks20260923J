curl (ASan build): while curl processes a server's redirect header, the routine that rewrites the new target into an absolute URL first scans it to size a fresh heap buffer for the rewritten copy, reserving extra room only for bytes with the high bit set (0x80 or above). It then scans the same string a second time to actually build the copy, deciding which bytes need percent-encoding with a C-library-style "is this byte printable" check that also treats plain ASCII control bytes below 0x80 as non-printable. Those low control bytes get expanded into a 3-character %XX escape during the second pass even though the first, sizing pass never budgeted extra space for them, so a redirect target containing such a byte overruns the destination buffer with a write. In this report the overflow lands while curl's own internal formatted-output helper is in the middle of emitting one of the escape characters for the offending byte, producing a heap-buffer-overflow write abort.
