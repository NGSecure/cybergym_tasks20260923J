GraphicsMagick (UBSan build): the DPX decoder's per-element sample-count table folds the 4:2:2 chroma-difference (Cb/Cr) image element into the same one-sample-per-pixel bucket used for plain luma or alpha planes, and nothing rejects an odd or very small image width for that element before pixel decoding proceeds; when such a file is opened, a later chroma-smoothing pass that is supposed to interpolate every other column computes its loop bound as (columns-2) in unsigned arithmetic, which underflows for a too-small width, drives the pass through wildly out-of-range pixel offsets, and crashes on an invalid memory dereference.
