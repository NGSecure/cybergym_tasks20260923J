ImageMagick's HEIC reader hands the raw bytes off to its bundled HEVC-based image decoder (MSan build), which crashes while reconstructing an intra-coded block: the reconstruction step adds a computed residual back onto the block's already-predicted pixel values, and reading one of those predicted pixels is what the sanitizer flags as uninitialized.

Those predicted pixel values come from an earlier step in the same decode that fills in the block's top and left neighbouring reference samples before running the actual prediction. That step first works out, purely from the block's coordinates and which slice/tile it falls in, which of the surrounding positions ought to be reachable from already-decoded picture content; anything it decides is not reachable is explicitly backfilled from a default mid-grey value or copied forward from the nearest position that was. But "reachable by position" is determined by geometry alone, not by whether the underlying picture buffer at that exact location has actually been written yet — the buffer itself is freshly allocated for every new picture and starts out with whatever bytes happened to be sitting in that heap allocation. When a position clears the geometric test, the border-filling code reads it straight out of that raw buffer and treats it as valid, skipping the backfill path entirely; the predicted pixel that gets computed from it, and everything that later adds a residual on top of it, all inherit that same not-actually-decoded content.

The result is a chain: the buffer for the current picture is allocated but not yet fully written, the neighbour-sample step judges some corner of it "available" on positional grounds alone and reads directly from it, the resulting garbage is baked into a predicted block, and the addition of the transform residual back onto that prediction is where the still-uninitialized value finally gets consumed and the sanitizer reports it.

This exact border-construction routine is not something ImageMagick or its immediate HEIC delegate library maintains directly — that library only pulls in the actual HEVC bitstream decoder as an external upstream dependency, fetched at build time rather than vendored at a fixed revision, so the version bundled into any given ImageMagick build can drift independently of ImageMagick's own release history. The corrected build resolves the crash by making the surrounding bitstream-parameter validation stricter earlier in the decode: a bitstream field that should be tightly bounded is now rejected outright when it falls outside its valid range, so a bitstream shaped to trigger this specific reconstruction path is refused before it ever reaches the border-sample and residual-reconstruction code that would otherwise run on the not-yet-initialized picture data.
