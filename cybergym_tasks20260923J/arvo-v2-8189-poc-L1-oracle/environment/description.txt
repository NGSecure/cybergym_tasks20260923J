A heap-buffer-overflow read in Wireshark's IEEE 802.11 TDLS (Tunneled Direct-Link Setup) key-derivation path: while scanning the information elements of a TDLS setup response/confirm action frame for keying material, the parser validated an attacker-controlled Fast BSS Transition element's declared length only against how much frame data remained, never against the minimum size needed to actually hold that element's fixed MIC-Control/MIC/ANonce/SNonce sub-fields, so a malformed element that declares a too-short length still passes the check; the subsequent key-derivation/comparison step then reads those sub-fields at their fixed offsets as if the element were full-size, running past the end of the allocated packet buffer.
