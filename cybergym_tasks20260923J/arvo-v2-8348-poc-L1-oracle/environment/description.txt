The flaw sits in the machinery that applies a per-image clip or composite mask while the image-decoding library is parsing a drawing-command image whose content defines such a mask. Establishing that mask on an image first (re)provisions the image's off-heap pixel-cache buffer and then walks the image pixel-by-pixel, writing the mask's channel values into that freshly (re)allocated buffer one synchronization pass at a time. The very same low-level routine that performs each of those writes is also responsible, on every invocation, for immediately re-consulting whatever mask is currently attached to the image and reapplying it back onto the pixel data being synced -- and before the fix this reapplication ran unconditionally, with nothing distinguishing "the mask is still in the middle of being written for the first time" from "the mask already holds complete, trustworthy data." Because the newly (re)allocated pixel-cache memory is not zero-filled on acquisition, only the portion actually written so far in the loop carries a meaningful value; everything past that point is leftover heap content that was never assigned. Since the reapplication step reads the mask's values from that same buffer regardless of how far the write pass has progressed, it can end up consuming bytes that fall well within the allocation's bounds but have never been stored to -- a single-threaded ordering problem, not an out-of-bounds access, where a read simply outruns the write that was supposed to happen before it. Those never-initialized bytes then flow onward as if they were legitimate mask/pixel data into further per-pixel processing carried out later in handling the same drawing command. The fix closes this by adding an explicit piece of state to the image that distinguishes "a mask channel is actively being (re)established right now" from "a mask channel already holds valid data," and makes the reapplication step check that state and skip itself for the duration of the establishment pass -- the size and layout of the underlying buffer are untouched; only the ordering between the write pass and the read-back that follows it is corrected. A related, secondary gap addressed in the same change ensures that one of the three categories of mask an image can carry is properly propagated when an image is duplicated or when its channels are recombined, so that category's state no longer silently diverges from the other two across such operations.
