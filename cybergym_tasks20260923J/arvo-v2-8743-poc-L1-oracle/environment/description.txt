GraphicsMagick's PNG reader suffers a 1-byte heap-buffer-overflow read while decoding a "Raw profile type ..." tEXt text chunk whose associated text value is empty. The raw-profile parser assumes every such chunk's text begins with a header line (a description followed by a newline and a decimal length field) and unconditionally starts scanning one byte past the start of the text looking for that newline; when the chunk's text is empty, libpng has backed it with a buffer too small to contain any newline at all, so the scan walks past the end of that allocation before finding one, producing the out-of-bounds read.
