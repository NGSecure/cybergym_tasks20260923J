ImageMagick crashes with a heap-use-after-free while pinging (header-only probing) a crafted MATLAB (.mat) image file. Root cause: the MAT decoder, when handling certain multi-part/complex numeric-class layouts, allocates a "secondary" image handle meant to represent an extra component of the matrix, but under some crafted layouts that secondary handle ends up aliasing the very same image object the decoder is about to return as its primary result — the decoder never checks for this aliasing before cleanup. It then unconditionally tears down the "secondary" handle (closing its underlying data stream and freeing the image structure), which in the aliased case actually destroys the primary image object that is still live; a later step further down the same decoding routine touches that primary object's data-stream field again, dereferencing the now-freed memory and triggering the use-after-free.
