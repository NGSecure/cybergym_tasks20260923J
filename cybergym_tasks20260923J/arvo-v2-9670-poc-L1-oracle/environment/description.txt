When ImageMagick decodes a HEIC image it hands the embedded HEVC bitstream off to its bundled HEVC/H.265 decoder, which walks a sequence of NAL units including sequence parameter sets (SPS) and picture parameter sets (PPS), each parsed into its own fixed-capacity table indexed by a small integer id carried in the bitstream. While parsing a PPS, the decoder reads the SPS id it references straight out of the bitstream and range-checks that value before using it, but the check is bounded against the capacity of the wrong table: the limit applied belongs to the larger table (the one that holds parsed PPS entries), not the smaller fixed-size array that actually backs the parsed SPS objects. Because that array is noticeably smaller, an attacker-supplied id can be large enough to fall outside its bounds while still passing the oversized check, so a subsequent lookup that simply tests whether an SPS with that id has already been parsed reads past the end of the fixed-size array. On a crafted/malformed HEIC input this manifests as an out-of-bounds array read, caught here by the sanitizer as undefined behavior rather than a hard crash, but reachable purely through image decoding with no other preconditions.
