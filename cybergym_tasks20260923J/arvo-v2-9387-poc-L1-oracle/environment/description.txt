Skia's raster-canvas text-drawing fuzz target (built with MemorySanitizer) hits a use-of-uninitialized-value read while preparing to draw positioned text. Skia's canvas text APIs stage each text draw through an internal buffer inside the glyph-run builder that pairs the glyphs to be rendered with a copy of the paint in effect for that call; this buffer is a single long-lived member reused across successive draw calls rather than freshly built and scoped to each call, and it is explicitly torn down before being repopulated for the next draw. When a draw call ends up with nothing to render (for example because the encoded text or its positioning collapses to an empty glyph run for that particular call), the repopulation step is skipped, so the buffer is left in its already-torn-down state instead of holding a fresh, valid paint. The very next operation that needs the paint's shader - Skia evaluates the current paint's shader to derive an approximate solid color for the glyph as part of choosing a font-scaler cache entry before rasterizing the text - dereferences the shader reference stored in that stale, torn-down copy. Because the shader had already been released when the buffer was torn down, the bytes backing that reference were produced by a heap deallocation rather than genuine initialization, which is what MemorySanitizer reports as a use of an uninitialized value. The underlying flaw is that nothing enforces the reused glyph-run/paint buffer being left in a fully valid state whenever a given draw call has nothing to render, yet the later code in the same draw path unconditionally treats the buffer's contents as a live, fully-initialized paint.
