A crafted TIFF image with a malformed EXIF directory triggers a stack-buffer overflow in ImageMagick's TIFF EXIF-property reader when it queries a particular short-typed EXIF tag. The reader classifies EXIF SHORT tags at compile time as either a single 16-bit scalar or a variable-length array, and for a tag it treats as scalar it declares only a bare 2-byte stack variable to receive the value before calling into the underlying TIFF library to populate it. The specific tag involved here is misclassified: the underlying TIFF library's own field definition for that tag is actually a short fixed-size array holding more than one 16-bit element, and the library's generic field accessor writes that field's full width according to its own internal definition, regardless of how large a destination buffer the caller actually provided. Because the caller's stack slot is undersized for what the library ends up writing, the write overruns the scalar variable and spills into neighboring local variables in the same stack frame, corrupting adjacent state — a classic mismatch between what the caller assumes a tag's value cardinality to be and what the parsing library's own metadata for that tag actually specifies.
