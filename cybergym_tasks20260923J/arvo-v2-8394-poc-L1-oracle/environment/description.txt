Heap-buffer-overflow write while ImageMagick renders an MVG `path` primitive whose data contains cubic/quadratic Bezier-style path commands. Root cause: before actually tracing the path, the parser pre-scans the raw path-data string to estimate how many point-array slots the primitive will consume, and grows a single heap-allocated buffer to that estimate; the point-tracing pass then writes each generated point into consecutive slots of that same buffer. SVG-style path syntax lets one curve-command letter be followed by an arbitrary number of implicit, repeated coordinate groups, and each such group independently expands into its own sizeable block of intermediate points once the curve is actually traced. The pre-scan estimator, however, only adds its per-curve capacity allowance at the single spot in the string where a parsed number happens to be immediately followed by a curve-command letter, instead of scaling that allowance with however many repeated coordinate groups actually follow the letter. For crafted/degenerate path data this makes the size estimate come in well below what the later curve-expansion pass really needs, so the buffer it grew to is undersized; as tracing keeps emitting new points into consecutive struct slots it runs past the end of the heap allocation and performs an out-of-bounds write of a pointer-sized struct field just beyond the buffer's end.
