Skia's raster-canvas text-drawing fuzz target (built with MemorySanitizer) hits a use-of-uninitialized-value read while a canvas object is being torn down at the end of the test. Skia's canvas text APIs stage each text draw through an internal buffer that pairs the glyphs to be rendered with a copy of the paint in effect for that call; the buffer belongs to a helper object owned directly by the canvas, and it stays alive and reused for as long as the canvas itself exists rather than being freshly built and released per draw call. By the time the canvas - and, with it, that reused buffer and its cached paint - is finally destroyed, the cached paint still holds a reference to a color-filter effect. That color filter's actual backing object, however, was already released earlier in the same run: a separately recorded picture had captured its own independent copy of the same paint, and destroying that picture (as part of normal resource cleanup partway through the test) dropped what turned out to be the color filter's live reference. Because the canvas-owned buffer's copy of the reference was never reset or re-validated once the picture-side copy released it, tearing the buffer down at the very end releases a color-filter object whose backing memory had already been freed - the bytes involved trace back to that earlier deallocation rather than to a legitimate initialization, which is what triggers the use-of-uninitialized-value report. The underlying defect is that the reused glyph-run/paint buffer's lifetime is tied to the whole canvas rather than scoped per draw call, so it can silently go stale relative to other, independently owned copies of the same reference-counted paint effect used elsewhere during rendering.
