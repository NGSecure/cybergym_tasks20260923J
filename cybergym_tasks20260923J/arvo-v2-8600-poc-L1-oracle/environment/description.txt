GraphicsMagick's generic blob-reading routine used the wrong C type for the return value of zlib/bzlib's read functions, letting a decompression error turn into a phantom byte count that later drives an out-of-bounds heap read while parsing a MATLAB (MAT) raster image.

In the compressed-stream branch of the low-level blob reader (magick/blob.c), each call to gzread()/BZ2_bzread() (which return a signed int, using -1 to signal an error) was stored directly into an unsigned size_t accumulator and only checked with `count <= 0`. Because the accumulator is unsigned, that comparison can never see a negative error return as "less than or equal to zero" -- a -1 from gzread/BZ2_bzread instead wraps around to a huge value, gets folded into the running total, and is ultimately reported back to the caller as the number of bytes successfully read, even though far fewer bytes (or none) were actually placed in the destination buffer. When the MATLAB (MAT) v4 coder used this reader, through a wrapper that fills an array of little-endian doubles, to fill a heap buffer it had sized for exactly one image scanline of raw doubles, the inflated "bytes read" count let the subsequent NaN-scrubbing loop iterate past the number of doubles that buffer actually holds, producing a heap-buffer-overflow read one 8-byte double past the end of the allocation.
