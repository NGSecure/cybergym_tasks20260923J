Heap-use-after-free in Wireshark's XnAP (Xn Application Protocol) PER dissector when it processes the RRC-Context payload field inside a UE-context handover-request PDU on an XnAP conversation that has already dissected an earlier packet. Root cause: the first PDU seen on a new XnAP conversation stores the two endpoint addresses into a conversation-scope struct meant to persist for the whole capture, but the address bytes themselves are duplicated with a wmem allocator scoped only to that single packet; once the packet-scope arena is torn down at the end of dissecting that first PDU, any later PDU that reaches the RRC-Context field and compares its destination address against the cached endpoint addresses (to decide which peer sent it) dereferences the already-freed address bytes.
